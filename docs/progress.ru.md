# AttendBack — выполнение плана

Основание: [утверждённый план](../hackathon-product-plan/development-plan.ru.md).
Пользователь одобрил реализацию всех этапов. Статусы отражают выполненные проверки, а не наличие файлов.

| Этап                 | Статус                                                     | Проверка / следующий результат                                                                                              |
| -------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 1. Основа            | Проверено                                                  | TypeScript, Vitest, production build; HTTP /api/health = 200 с database:true; worker --once подключился к PostgreSQL 18.4   |
| 2. Правила           | Проверено                                                  | docs/protocol.ru.md; 4 проверки денежных правил; миграция PostgreSQL применена и повторена                                  |
| 3. Базовая программа | Проверено                                                  | SBF + Anchor IDL + Codama; 4 LiteSVM-сценария с реальными SPL-переводами                                                    |
| 4. Неявки и споры    | Проверено                                                  | 7 LiteSVM-тестов: споры, временные границы, 0–100% удержания и откат обеих частей выплаты                                   |
| 5. Сервер            | Проверено                                                  | 7 серверных тестов + RPC-сценарий v1/v0; 60 заявок на последнее место; восстановление 17 таблиц                             |

| 8. Проверки          | Проверено                                                  | 17 тестов программы/правил, 13 PostgreSQL/RPC-тестов, 6 браузерных сценариев; исправления и docs/review.html                |
| 9. Devnet            | Локальный пакет готов; внешний запуск ожидает конфигурации | docs/devnet-release.ru.md, проверка genesis/mint, хеши SBF/IDL, сценарий и записи демо; devnet deploy ещё не выполнен       |

Сейчас отсутствуют подтверждённые параметры публичного размещения и пользовательский кошелёк для devnet-развёртывания. Это не препятствует локальной реализации и проверкам.

Этап 7: обе production-сборки проходят; 16 модульных/программных и 10 серверных проверок проходят; 3 браузерных проверки проходят. Камера реализована через getUserMedia + jsQR с ручным вводом; физическое мобильное устройство и HTTPS-домен ещё не проверялись.

Этап 8: пройдены все 6 браузерных сценариев (общий прогон и адресные повторы после исправлений). Камера проверена в полноценном Chromium на Y4M-потоке с настоящим QR. Физический телефон и публичный HTTPS-домен — проверка после размещения. Найдены и исправлены рассогласование часов, повторный check-in после коррекции, потеря проекции, доступ к описанию чужого спора и утечка черновиков. Production npm audit: 0 advisory; это не независимый аудит. Восстановление 17 таблиц PostgreSQL вновь прошло. CI-конфигурация обновлена, GitHub workflow ещё не запускался.

Этап 9: подготовлены `.env.devnet.example`, `release:check`, `release:manifest`, инструкция размещения и сценарий демонстрации. Повторно прошли TypeScript и production build после настройки recovery URL. Read-only запросы подтвердили официальный genesis devnet, SPL-владельца и 6 знаков тестового mint; хеши и оценка rent записаны в `docs/release-manifest.json`. Проверка незаполненной devnet-конфигурации ожидаемо прекращается до сетевых действий. Успешные записи браузера сохранены в `.local/demo-video/organizer.webm` и `attendance.webm`.

Продолжение этапа 9: реализован `apps/signer` — отдельный сервер с проверкой точного сообщения, on-chain состояния, devnet genesis, mint, ролей, комиссии и симуляции. Пройдены 13 новых тестов signer, включая HTTP на localhost и совместимость backend с v0/v1; общий прогон — 30 тестов. Конфигурация `.env.signer.example`, шаблон systemd и описание границ доверия — в `docs/signer.ru.md`. На этом шаге используются только сгенерированные в памяти тестовые ключи; служебные секреты для devnet не создавались.

При финальном показе этапа 9 обнаружено и исправлено упущение этапов 7–8: страница события ещё сравнивала bookingClose с часами устройства. Теперь бронирование использует тот же Clock Solana, что и сервер; при недоступности часов действие отключено с пояснением. Новый седьмой браузерный сценарий прошёл: дата устройства 2099/2000, закрытие по времени сети, ошибка RPC и восстановление. TypeScript и production build повторно прошли после исправления.

Осталось для завершения этапа 9: выбрать публичный deploy fee payer и upgrade authority, разместить signer и настроить три сервисных адреса/секреты, выбрать хостинг/стоимость, выполнить согласованный deploy и HTTPS-размещение, затем повторить сценарии с обычным кошельком и физическим телефоном. Клиент и сервер подписи реализованы; внешнее размещение ещё не выполнено. Код сохраняется локальными коммитами; push, запуск GitHub CI и отправка заявки не выполнялись.
