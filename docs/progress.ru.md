# AttendBack — выполнение плана

Основание: [утверждённый план](../hackathon-product-plan/development-plan.ru.md).
Пользователь одобрил реализацию всех этапов. Статусы отражают выполненные проверки, а не наличие файлов.

Облачный выпуск от 9 октября 2026: [AttendBack](https://attendback-three.vercel.app) работает на Vercel Hobby с Neon Free. Программа опубликована в devnet; выгруженный SBF совпал с проверенным SHA-256, upgrade authority сохранён отдельно. Все 7 миграций создали 17 таблиц, immutable-policy trigger проверен. Signer отвечает 200 с токеном и 401 без него.

Сквозная облачная проверка: отдельные сгенерированные организатор и гость, публикация условий, 1 тестовый USDC, QR-токен, автоматический возврат через Workflow и изолированный signer. [Расчёт finalized](https://explorer.solana.com/tx/3BH1NYnYx6ryz59wLtWYc27YYSeujqRKdEse2Z4pj7mWdRjLvnH5Hy4PgrPdvzi9ucSrAdLHD4ABQaLuzUS6zyh2?cluster=devnet): refund 1 USDC, penalty 0, билет Active, залог Settled; баланс гостя восстановился с 1 до 2 USDC. Локальный worker в этой проверке не участвовал. Клиент — проверочный скрипт через HTTPS API, поэтому обычный кошелёк и камера телефона ещё не подтверждены.

Исправление, найденное при облачной проверке: получатель удержаний больше не резервирует место для собственного залога; API возвращает понятный PENALTY_RECIPIENT вместо ошибки симуляции 503. Проверены TypeScript и локальный интеграционный тест с настоящими PostgreSQL/RPC: отказ не занимает место, отдельный гость успешно вносит залог. Подробности и подписи: [протокол выпуска](deployment-2026-10-09.ru.md), [манифест](release-manifest.json). Платные тарифы не подключались. GitHub CI для опубликованного кода `849cfb6` завершился успешно: [run 37900390698](https://github.com/ernur077sss-art/AttendBack/actions/runs/37900390698).

История предыдущих проверок ниже сохранена как хронология; её прежние ограничения заменены текущим статусом выше.

Повторная сверка от 8 октября: [отчёт по каждому критерию и исправлениям](plan-audit.ru.md). План ещё не закрыт целиком: этап 7 требует проверки физического телефона по HTTPS, этап 9 — согласованного внешнего размещения. Исторические результаты ниже не заменяют эти проверки.

Публикация от 8 октября: исходники, документация и история разработки отправлены в ветку `main` репозитория [ernur077sss-art/AttendBack](https://github.com/ernur077sss-art/AttendBack). На момент первой публикации удалённый коммит реализации совпал с локальным: `fcd7dfeb22bb21e73c26cea572d324a7778ce7ce`. [Первый запуск GitHub Actions](https://github.com/ernur077sss-art/AttendBack/actions/runs/37773573977) начался; его итог в этом журнале ещё не зафиксирован. Подготовка Vercel, этап 9: добавлены отдельные workspace-пакеты и Vercel-конфигурации для web/API и recovery, file tracing общего кода, пул PostgreSQL с `attachDatabasePool`, проверка переменных до сборки и в публичном API, точный origin Preview без доверия к Host. Основной API ограничен 120 секундами; постоянный worker и изолированный signer размещаются отдельно. Подготовлены `.env.vercel.example`, исключения локальных файлов и [инструкция импорта](vercel.ru.md). TypeScript, 42 модульных/программных/signer/конфигурационных теста, 16 PostgreSQL/RPC-тестов (148,39 с), обычная production-сборка web, `build:vercel` с синтетической devnet-конфигурацией без сетевых обращений и recovery build прошли. Проверены frozen-lockfile установка трёх workspace-пакетов и наличие файлов runtime в trace API. Незаполненная конфигурация ожидаемо останавливает `vercel:check`. Первый запуск тестов потребовал разрешения localhost-сокета и запуска остановленного локального PostgreSQL/RPC; итоговые проверки выполнены после восстановления стенда. Дополнительно прошёл браузерный сценарий «залог → однократный QR check-in → finalized-возврат с активным билетом» (1/1, 54,6 с вместе с запуском стенда). Облачный deployment, provisioning внешних сервисов и devnet-развёртывание в рамках этой подготовки не выполнялись.
